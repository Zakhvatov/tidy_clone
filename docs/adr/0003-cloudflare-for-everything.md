# Cloudflare на всё: хостинг, посредник и генерация картинок

PWA не может обращаться к AI-API напрямую: `api.cloudflare.com` не отдаёт CORS-заголовки, а
`opencode.ai` разрешает CORS только для GET, не для POST. Значит нужен посредник. Одновременно
нужны хостинг статики и генерация изображений — а бесплатные лимиты у сторонних сервисов на порядки
хуже: remove.bg даёт ~50 вызовов в месяц, Hugging Face не даёт бесплатных кредитов вовсе,
Replicate вообще закрыт для браузера. Поэтому **один аккаунт Cloudflare закрывает все три задачи**:
Pages для статики, Worker как посредник и Workers AI для генерации.

Проверено вживую (воркер `tidy-ai-test`): `@cf/black-forest-labs/flux-1-schnell` отдаёт готовый
JPEG 1024×1024 за **~1.2 секунды**, вес 440–770 КБ. Бесплатные лимиты: **10 000 нейронов в день**
(Workers AI) и **100 000 запросов в день** (Workers).

## Рассмотренные варианты

- **remove.bg / Hugging Face / fal.ai напрямую из браузера** — отвергнуто: CORS они разрешают, но
  бесплатные лимиты несопоставимы (50 вызовов в месяц против ~130–500 картинок в день), а
  генерации у remove.bg нет вообще.
- **Свой VPS как посредник** — отвергнуто: единственный вариант с реальными деньгами (~150–300 ₽/мес),
  нужен только если Cloudflare окажется недоступен из РФ.
- **Всё локально на Mac (BiRefNet)** — отвергнуто как основной путь: M1 с 8 ГБ не тянет генерацию
  (1–3 минуты на картинку, диск впритык), а Mac должен быть постоянно включён.

## Последствия

- Токены и ключи живут в Worker, а не в телефоне. Посредник же снимает CORS.
- Генерация расходует общий дневной лимит нейронов: массовая оцифровка гардероба растягивается на
  дни. Для личного использования это незаметно.
- **Не проверено и требует проверки на чистой сети:** доступность `*.workers.dev` и `*.pages.dev` из
  РФ. Тест с Mac разработчика недостоверен — на нём подняты VPN (`TrueVPN`, `Turbo VPN`, `V2BOX`,
  четыре активных `utun`), из-за чего `curl` и Chrome ходят разными маршрутами.
- **Найден и подтверждён сбой доступа к `*.workers.dev` в браузере.** Домен отдаёт AAAA-запись
  (`2a06:98c1:3121::1`), а на Mac нет глобального IPv6 (только `::1` и link-local). Chrome пытается
  идти по IPv6, не получает маршрута и висит вместо быстрого отката на IPv4. Принудительный IPv6 в
  Chrome даёт `ERR_ADDRESS_UNREACHABLE`, принудительный IPv4 — успешную загрузку. `curl` с
  российского IP (188.243.183.68, SkyNet) достаёт воркер за 0.2 с — то есть блокировки нет, дело в IPv6.
  Это тот же класс проблемы, что и у пользователей в РФ на сетях без IPv6.
- **Решение:** собственный домен на Cloudflare с выключенным IPv6 (`Network → IPv6 compatibility: Off`).
  Тогда у домена вообще нет AAAA-записи и Happy Eyeballs нечего пробовать. Стоит ~200–300 ₽/год —
  единственная статья расходов во всём проекте. Временно можно обойтись без него, если тест на
  телефоне жены покажет, что Safari этой проблеме не подвержен.
