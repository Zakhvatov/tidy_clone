# ADR-0008 · AI-версия всегда с прозрачным фоном

Статус: принято (22.10.2026). Дополняет ADR-0002 и ADR-0006.

## Контекст

До сих пор AI-версия рисовалась на «plain pure white background»: так было проще и для
каталожного вида, и для точного выреза пакшота. Но в образе белый квадрат вокруг вещи — это
видимый шов: коллаж на coloured-подложке выглядит как набор вклеенных прямоугольников.
Пользователь попросил, чтобы генерация одежды сразу давала прозрачный фон.

Провайдер IskraGen поддерживает прозрачность неодинаково (каталог `GET /v1/catalog/`,
проверено 22.10.2026):

- `gpt-image-2-text-to-image` и `gpt-image-2-image-to-image` принимают
  `params.background: "transparent"` (только при `resolution: 1K`);
- `nano-banana-2-1`, Grok, Flux, Qwen такого параметра в `paramsSchema` не имеют —
  альфу можно получить только обработкой уже готового кадра.

## Решение

Прозрачность обеспечивается на двух уровнях, чтобы она не зависела от выбранной модели.

### 1. Нативный прозрачный фон у моделей, которые его умеют

`workers/api/src/models.ts` получает признак `transparentBackground`. Для моделей
`gpt-image-2-text-to-image` и `gpt-image-2-image-to-image` воркер добавляет в `params`
`background: "transparent"` (кадр уже 1K). Модель по умолчанию для image-to-image
меняется с `nano-banana-2-1` на `gpt-image-2-image-to-image`: при обычном сценарии
«фото → AI-версия» прозрачность приходит от провайдера, без клиентской обработки.

Цена дефолта растёт с 4 ₽ до 7 ₽ за кадр — это осознанная плата за альфу. Пользователь
по-прежнему может выбрать более дешёвую модель в пикере; тогда работает второй уровень.

### 2. Клиентская нормализация для всех остальных моделей

После скачивания готового кадра клиент вызывает `ensureTransparentPng`:

1. если в PNG уже есть альфа-канал с прозрачными пикселями — кадр не трогается;
2. иначе вызывается существующий точный вырез (`makeCutout`) по почти-белому фону;
3. если вырез «подозрительный» (светлая вещь, фон не распознан) — сохраняется исходный
   кадр, а не испорченный;
4. результат кодируется в PNG и сохраняется с MIME `image/png`.

Обработка идемпотентна и дешёвая: JPEG/PNG декодируется один раз, повторный вызов на
PNG с альфой сразу возвращает исходный blob. Ошибка декодирования (jsdom, старый webview)
не ломает генерацию: возвращается исходный blob.

Промпт получает `no shadow`: тень — главный источник грязной кромки при white-key вырезе.
Фон в промпте остаётся почти-белым, потому что это самый предсказуемый вход для моделей
без нативного параметра; нативный `background: transparent` имеет приоритет у GPT Image.

## Последствия

- В сетке, коллаже и карточке AI-версия не приносит белый прямоугольник.
- История генераций в KV хранит то, что скачал воркер. Для нативных моделей это уже PNG
  с альфой; для остальных история хранит исходный кадр, а прозрачность применяется при
  «Забрать в гардероб». Это осознанно: воркер не занимается попиксельной обработкой.
- Перегенерация от AI-версии (ADR-0006 §4) отправляет референсом PNG с альфой — провайдер
  принимает PNG, поэтому цепочка не ломается.
- `cutoutBlob` (T9) остаётся отдельным путём для пакшотов; `ensureTransparentPng` использует
  его ядро `makeCutout`, но не помечает результат как `вырез` и не меняет роль изображения.
- Живая проверка тратит деньги: одну генерацию с прозрачным фоном нужно проверить вручную
  на устройстве (альфа, кромка, отсутствие тени).
