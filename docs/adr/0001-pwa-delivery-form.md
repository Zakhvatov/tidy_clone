# Форма поставки: PWA, а не нативное iOS-приложение

Клон Tidy делается для личного использования одним человеком (жена автора) на iPhone. Нативное
приложение потребовало бы Xcode (~40–50 ГБ, при 28 ГБ свободных на диске), а бесплатная сборка под
личным Apple ID живёт 7 дней и требует переподписи; TestFlight требует Apple Developer Program за
$99/год с оплатой, недоступной из РФ. Поэтому приложение поставляется как **PWA**: статическая
веб-сборка, добавляемая на экран «Домой» Safari, без App Store, без Apple ID, без срока жизни и без
затрат на распространение.

Ключевой пользовательский сценарий — «вставить ссылку на товар с Wildberries» — не требует ни одной
нативной возможности: это обычный ввод текста плюс сетевой запрос. Импорт товара WB целиком выполним
из браузера (статика `basket-*.wbbasket.ru` отдаёт и фото, и метаданные с `access-control-allow-origin: *`),
поэтому бэкенд не нужен.

## Рассмотренные варианты

- **Нативная сборка через Xcode + бесплатный Apple ID** — отвергнуто: Xcode не установлен и не
  помещается на диск; сборка перестаёт работать через 7 дней и требует переподписи.
- **AltStore / SideStore (сайдлоад)** — отвергнуто: требует постоянно доступный Mac или ПК как сервер
  подписи, хрупко в быту.
- **Apple Developer Program + TestFlight** — отвергнуто: $99/год, оплата из РФ проблематична, билд
  живёт 90 дней, для сборки всё равно нужен Xcode или macOS-CI.
- **App Store** — отвергнуто: ревью, оплата, и приложение является клоном существующего продукта.

## Последствия

- Системный шит «Поделиться → приложение» недоступен. Вместо него — копирование ссылки из WB и
  вставка в поле ввода. Это соответствует исходному сценарию пользователя.
- Нет доступа к нативным API (Vision subject-lifting, Core ML). Удаление фона, если понадобится,
  придётся делать в браузере (ONNX/transformers.js) или на сервере.
- Хостинг — статика. Требуется HTTPS для service worker; выбор конкретного хостинга — обратимое
  решение и в ADR не фиксируется.
