# ADR-0006 · Генерация AI-версии: загрузка фото → подтверждение со стоимостью → асинхронный job

Статус: принято, утверждено владельцем продукта (20.10.2026).

## Контекст

После перехода на image-to-image (D13) выяснилось, что:

1. **Синхронная генерация ненадёжна.** `POST /generate` держит соединение до готовности
   картинки; на медленных моделях это 40–95 с — упирается в дедлайн клиента (95 с) и в
   нестабильную сеть. Пользователь видит «Не удалось связаться с сервисом», хотя воркер
   и провайдер работают (живой прогон D13: 200 за 39 с).
2. **Интерфейс запутан.** Два входа (ссылка и фото), генерация запускается «сразу и молча»,
   без показа модели и стоимости, статуса нет.
3. **Две копии изображения ни к чему.** Пользователь загружает снимок только как сырьё для
   оцифровки; хранить его рядом с готовой AI-версией в галерее не нужно.

## Решение

### 1. Вход один: «Загрузить фото»

Поле «Ссылка на товар с Wildberries» и кнопка «Найти вещь» **удаляются из интерфейса**.
Импорт по ссылке из продукта уходит; словарь домена (`CONTEXT.md`, термин «Импорт по
ссылке») и WB-модули не удаляются в этом изменении — они просто не вызываются из UI
(удаление отдельным решением, после подтверждения).

### 2. Флоу генерации — с подтверждением и ценой

1. Загрузка фото → распознавание категории (как сейчас).
2. Экран подтверждения перед генерацией: превью загруженного, **пикер модели**, рядом
   **стоимость из каталога воркера** (₽ за кадр), кнопка «Сделать AI-версию · 4 ₽».
3. Генерация стартует **только после подтверждения**. Фоновых и мгновенных генераций нет.

### 3. Асинхронная генерация: id → статус-экран → авто-опрос

Контракт воркера (клиент общается только с воркером, ключа провайдера у него нет):

- `POST /generate` → **202** с `taskId`: воркер создаёт генерацию у провайдера и
  отвечает сразу (1–3 с), картинку не ждёт. Синхронный режим (дождаться картинки одним
  запросом) из продукта уходит; дедлайн ожидания генерации отменяется, остаётся только
  на загрузку референса и скачивание файла.
- `GET /generate/{taskId}` → короткий JSON-статус (`PENDING` / `PROCESSING` /
  `SUCCEEDED` / `FAILED` + `costRub`). `FAILED` — деньги провайдер вернул уже сам.
- `GET /generate/{taskId}/image` → байты картинки, только после `SUCCEEDED`. Скачивание —
  **отдельным запросом**, а не полем статус-ответа: файл ~250 КБ не должен висеть в теле
  опроса, который клиент дёргает каждые 3 с.
- Клиент показывает **экран статуса**: прогресс-бар, **авто-опрос каждые ~3 с**
  (по готовности ответа — сразу), ручная кнопка «Обновить» как фолбэк. При `SUCCEEDED`
  клиент скачивает файл и кладёт картинку в каталог вещи.

Надёжность — идемпотентность и возобновление:

- **`Idempotency-Key`** (≤64 символов, детерминированно от вещи и модели) генерирует клиент
  и пробрасывает через воркер в провайдер: повторный `POST` с тем же ключом возвращает
  **уже существующую задачу без повторного списания**. Потерянный ответ `POST` (обрыв сети,
  закрытая вкладка) не стоит второй оплаты.
- **`taskId` и ключ сохраняются в IndexedDB** вместе с задачей очереди (T12). Закрытие
  вкладки после `202` работу не теряет: при следующем открытии опрос продолжается, а
  готовое забирается кнопкой «Забрать готовое».
- **Потолок ожидания 5 минут — потолок живого сеанса, а не отказ.** По его истечении
  задача помечается «не удалось», но `taskId` сохраняется: «Повторить» означает
  **допросить статус той же задачи**, а не оплатить генерацию заново.
- Опрос идёт только когда вкладка видима (`visibilitychange`): при скрытой — пауза,
  при возврате — немедленный опрос.
- Лимиты: `POST /generate` — 5/мин на IP (уже так), статус — 60/мин, скачивание — 10/мин.
  Параллелизм генераций не выше **5 одновременных** (лимит провайдера, D12): очередь
  не ставит новую задачу, пока заняты все пять.
- Исправляется баг `fetchWithTimeout` воркера: таймаут снимался после прихода заголовков
  и не покрывал чтение тела, поэтому скачивание файла могло висеть без ограничения —
  прямая причина сообщения «Не удалось связаться с сервисом» при живом воркере.

### 4. Хранение: остаётся только перегенерированная картинка

Загруженный снимок — **сырьё**, а не экспонат. После успешной генерации из галереи вещи
удаляется загруженный Оригинал; в галерее остаётся одна AI-версия.

Это **сознательное исключение** из правила «Оригинал никогда не удаляется» (CONTEXT.md):
правило действует для источников, которые нужны для повторной работы, — здесь источником
на момент перегенерации становится уже сама AI-версия (она каталожная, с белым фоном,
пригодна как референс i2i). При **неуспешной** генерации снимок сохраняется, пока пользователь
не удалит вещь или не повторит генерацию.

## Цена и выбор модели

- Стоимость берётся из каталога `GET /models` (поле цены); если каталог недоступен —
  из резервного списка `generation-models.ts`.
- Выбор модели хранится в localStorage и подставляется в следующее подтверждение.
- Пикер модели и подтверждение стоимости — **только в карточке вещи**. Массовое
  «Оцифровать всё, где нет пакшота» остаётся без пикера и без подтверждения цены:
  идёт дефолтной i2i-моделью, стоимость перед запуском не показывается
  (решение 20.10.2026, D15; известное следствие — бюджет массового запуска не виден).

## Критерии готовности

- [ ] Форма добавления: только «Загрузить фото»; поле ссылки отсутствует.
- [ ] Перед генерацией — экран подтверждения с выбранной моделью и её ценой.
- [ ] `POST /generate` возвращает id; картинка одним запросом не блокируется.
- [ ] Экран статуса: прогресс, авто-опрос ~3 с, кнопка «Обновить».
- [ ] По успеху: AI-версия в каталоге, загруженный снимок из галереи удалён.
- [ ] По ошибке/таймауту 5 мин: понятное сообщение, оригинал сохранён, «Повторить» работает.
- [ ] Массовая «Оцифровать всё» использует тот же async-путь.
- [ ] `taskId` и `Idempotency-Key` сохраняются в IndexedDB; повтор создания с тем же ключом
      не приводит к второй генерации и второму списанию.
- [ ] Закрытие вкладки после старта и повторное открытие: задача находится, картинка
      добирается («Забрать готовое»); «Повторить» после 5 минут допрашивает статус,
      а не оплачивает заново.
- [ ] Опрос на скрытой вкладке стоит на паузе; лимиты статуса и скачивания заданы;
      чтение тела в воркере ограничено таймаутом.
- [ ] Живая проверка (одна платная генерация): создание → закрыть вкладку → открыть →
      картинка забрана; повтор `POST` с тем же ключом → та же задача, баланс не изменился.
- [ ] Тесты: клиент (старт/опрос/сохранение/деградация/возобновление), воркер (202 +
      статус-эндпоинт + скачивание + идемпотентный повтор).

## Последствия

- Исчезает проблема 95-секундного дедлайна и «обрывов» на длинных запросах.
- Один вход в приложение — проще и предсказуемее.
- Повторная смена модели возможна от AI-версии (каталожный вид — валидный референс).
- Оплаченная генерация больше не может потеряться: идемпотентный ключ и сохранённый
  `taskId` гарантируют, что обрыв связи не приводит ни к двойной оплате, ни к утере
  результата (остаётся внешний риск: срок хранения результата у провайдера неизвестен —
  есть только обязательство оферты хранить историю генераций в Личном кабинете).
