# Рабочий поток: оркестрация саб-агентов

Координатор — основной агент сессии. Он не делает всю работу руками: он нарезает задачи, запускает
саб-агентов, поллит их статус, принимает результат, коммитит и пушит.

## Роли

| Роль | Файл роли | Что делает | Код не правит |
|---|---|---|---|
| worker | `tools/agents/roles/worker.md` | реализует одну задачу | нет |
| reviewer | `tools/agents/roles/reviewer.md` | ревью дифа: стандарты + требование | да |
| tester | `tools/agents/roles/tester.md` | независимо ломает сделанное, ищет дефекты | да |
| auditor | `tools/agents/roles/auditor.md` | сверяет «Готово когда» с доказательствами | да |
| coordinator | эта сессия | нарезка, запуск, поллинг, приёмка, коммит, пуш | да |

## Запуск

```bash
tools/agents/run.sh worker   t4-parser   .agents/prompts/t4.md            # правит рабочее дерево
tools/agents/run.sh reviewer t4-parser   .agents/prompts/t4-review.md     # read-only
tools/agents/run.sh tester   m1-import   .agents/prompts/m1-test.md       # на отдельном worktree
tools/agents/run.sh auditor  m1          .agents/prompts/m1-audit.md
tools/agents/poll.sh m1                                                    # статус
```

Агент запускается в фоне (процесс `pi -p --no-session`), пишет лог в `.agents/logs/<role>-<task>.log`
и статус в `.agents/logs/<role>-<task>.status` (`running` / `done:0` / `failed:N`).
Координатор не ждёт в цикле: он поллит `poll.sh` между своими делами. Если задача очевидно долгая —
разумно вернуться к ней через несколько минут, а не стоять над ней.

## Порядок работы над задачей

1. **Нарезка.** Координатор читает тикет в `docs/tickets.md`, пишет промпт в `.agents/prompts/<id>.md`
   с точной формулировкой «Готово когда» и границами.
2. **Реализация.** `worker` пишет код и тесты, прогоняет сборку/типы/тесты.
3. **Ревью.** `reviewer` читает диф. `request-changes` → правки возвращаются worker'у.
4. **Тест.** `tester` на отдельном worktree/копии независимо проверяет сценарий, включая негативные кейсы.
5. **Аудит.** `auditor` сверяет требование с доказательствами по всему этапу.
6. **Приёмка.** Координатор читает отчёты (кратко), прогоняет финальные проверки сам, коммитит, пушит.

## Доказательства

Каждый пункт «Готово когда» оставляет след в `docs/evidence/`:

- `<ticket>.md` — что проверено, какой командой, какой результат, где лог/скриншот;
- сырые артефакты — в `docs/evidence/raw/` (логи тестов, JSON-выгрузки, скриншоты).

Правило: нет доказательства — пункт не выполнен.

## Границы и запреты

- Пересматривать ADR-0001..0005 нельзя. Смена решения — только через запись в `docs/open-questions.md`.
- Секреты (ключи Workers AI, `opencode-go`) живут только в воркере. В клиент не попадают никогда.
- Оригинал изображения неизменяем и не удаляется. AI-версия всегда помечена.
- Генерация картинок — только по явному нажатию.
- Вне объёма: AI-стилист, cost-per-wear, чемодан, ресейл, детский гардероб, синхронизация устройств,
  бренд и цена, поиск по WB.
- Один worker за раз на общем рабочем дереве; параллельные workers — только в отдельных worktree.

## Ветки и коммиты

- Рабочая ветка — `master`, origin `https://github.com/Zakhvatov/tidy_clone.git`.
- Сообщения коммитов — по-русски, в стиле существующих: `<Область>: <что сделано>`.
- Координатор коммитит после каждой принятой задачи и пушит. Долгих расхождений с origin не держим.
- `.agents/` (логи, промпты запусков) не коммитится; `docs/evidence/` коммитится.
