## 1. Что сделано и где лежит

### T22 · Токен доступа

| Артефакт | Что внутри |
|---|---|
| `src/storage/settings.ts` + тест | чтение/сохранение/очистка токена в localStorage (`tidy.accessToken`), маскирование; localStorage может быть недоступен — не бросает |
| `src/services/tidy-api.ts` | `resolveClientToken`: явный параметр → токен с устройства; **`VITE_TIDY_CLIENT_TOKEN` не читается**; при отсутствии токена и сети запрос не отправляется — понятный `unauthorized`; `validateAccessToken` через `GET /session` |
| `src/app/screens/AccessScreen.tsx` + css + тест | экран `/access`: ввод паролем, проверка `/session`, сохранение, маскированный текущий токен, «Забыть токен», понятные 401/503/сеть |
| `src/app/screens/BackupScreen.tsx` | карточка «Доступ к генерации»: статус, маскированный токен, ссылка на `/access` |
| `src/app/screens/AddItemForm.tsx` | ошибки `TidyApiError` показываются как есть (нет токена → «Введите его в разделе „Данные“») |
| `src/app/App.tsx` | маршрут `access` |
| `workers/api/src/index.ts` | секреты `ACCESS_TOKENS` (список через запятую) + `CLIENT_TOKEN`; constant-time сравнение со **всеми** токенами без раннего выхода; `GET /session` → `{ok:true}` под лимитером 30/мин |
| `.env.example`, `.github/workflows/deploy-pages.yml`, `src/vite-env.d.ts` | env-токен удалён из сборки и из CI |

**Метаданные вещи в генерации (подготовка истории):** `createGeneration`/`runGeneration`/
`digitizeItem` передают `itemId`/`title`/`category`/`subcategory`; воркер принимает их
опционально (`POST /generate`), старые клиенты работают без них.

### T23 · История генераций

| Артефакт | Что внутри |
|---|---|
| `workers/api/src/index.ts` | KV-namespace `GENERATIONS` (`wrangler.jsonc`, id `1aa481e7801348c2bde3f88bb658b34d`); `pending:{taskId}` с TTL 7 дней при постановке задачи; при скачивании — `gen:{taskId}` (байты + metadata ≤1024 байт с обрезкой), повторное скачивание не затирает metadata; `GET /generations` (list с metadata, сортировка createdAt desc, 503 без binding, лимит 30/мин); `GET /generations/{taskId}/image` (байты, 404, cache-control immutable, лимит 60/мин); сбой KV не ломает генерацию |
| `src/services/generations-history.ts` + тест | `listGenerationHistory` (битые записи пропускаются, `items` не массив → `invalid_response`), `downloadHistoryImage`, `restoreGeneration`: идемпотентно по `ai-{taskId}` (проверка до сети), дописывает AI-версию к живой вещи `itemId`, иначе создаёт `restored-{taskId}` без Оригинала с категорией из таксономии или «Разное», откат вещи при сбое сохранения |
| `src/app/screens/GenerationsScreen.tsx` + css + тест | вкладка «Генерации»: без токена → ссылка на `/access`, список с превью (параллелизм 2, object URL освобождаются), «Обновить», «Забрать в гардероб» → «Уже в гардеробе» / «Открыть вещь», человеческие 401/429/503/сеть |
| `src/app/AppLayout.tsx` | шестая вкладка «Генерации» (`ClockCounterClockwise`) между «Образы» и «Данные» |
| `src/app/screens/ItemScreen.tsx` | вещь без Оригинала (восстановленная) открывается: переключатель из существующих ролей, дефолт AI, бейдж «AI-версия», пустой URL не ломает разметку |

## 2. Живой прогон задеплоенного воркера

Воркер `tidy-api` задеплоен (version `c0f23ade-919f-45c3-bbd3-a994ef5eacc8`), KV-namespace
`TIDY_GENERATIONS` создан и привязан; секреты `ACCESS_TOKENS`/`CLIENT_TOKEN` перезаписаны
новым токеном (старый — из публичного бандла — инвалидируется):

| Проверка | Результат |
|---|---|
| `GET /health` | `{"ok":true,"generate":true,"classify":true}` |
| `GET /session` с новым токеном | 200 |
| `GET /session` со старым токеном (был в бандле) | 401 `unauthorized` |
| `GET /generations` с новым токеном | `{"items":[]}` — чистый KV, содержимого нет |
| `POST /generate` без токена (из UI) | запрос не отправляется, честный текст «Нужен токен доступа…» |

## 3. Автотесты

`docs/evidence/raw/t22-t23-checks.txt`: фронт 414 тестов (40 файлов), воркер 124 теста;
`tsc --noEmit`, `eslint`, `vite build`, `wrangler deploy --dry-run` — зелёные.

Ключевые проверки воркера: несколько токенов из `ACCESS_TOKENS`+`CLIENT_TOKEN`; `/session`
200/401/503; pending пишется при создании; download пишет `gen:`-запись и удаляет pending;
романтированная история отсортирована; при падении KV download всё равно 200; повторное
скачивание не затирает metadata; `/generations` без binding → 503.

Ключевые проверки фронта: токен «вошёл/вышел» через `/access` и «Данные»; без токена запросы
к воркееру не ходят; восстановление к живой вещи, создание `restored-*`, идемпотентность,
откат; экран истории: пусто/список/забрать/401; карточка вещи без Оригинала.

## 4. Остался шагом человека

- ввести новый токен на устройстве («Данные» → «Доступ к генерации») — живой токен в `.env.local`
  (`TIDY_ACCESS_TOKEN`) и `workers/api/.dev.vars`;
- полный живой цикл: сгенерировать → удалить вещь → вернуть из вкладки «Генерации»;
- удалить секрет `VITE_TIDY_CLIENT_TOKEN` из настроек репозитория GitHub (iOS-workflow его больше
  не читает, но строке это стоит добить руками: `gh secret delete` отсюда падал сетевым таймаутом);
- задеплоить фронт (страница Pages обновится после коммита и пуша в `master`).
