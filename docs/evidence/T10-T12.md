## 2. Единый клиент воркера (T10.1)

`tidy-api.ts` — единственное место, где собирается заголовок `x-tidy-client`,
читается `VITE_TIDY_API_URL`/`VITE_TIDY_CLIENT_TOKEN`, ставится таймаут и
разбирается тело ошибки. `classify-photo.ts` больше не содержит ни `apiBaseUrl`,
ни `clientTokenFromEnv`, ни `errorFromResponse` — он импортирует `requestJson` и
реэкспортирует `DEFAULT_API_URL`/`apiBaseUrl`/`clientTokenFromEnv`/`ClassifyError`
ради обратной совместимости. `ClassifyError` — это алиас `TidyApiError`, поэтому
`instanceof` и коды у распознавания и генерации одни и те же.

Коды: `unauthorized` (401) и `rate_limited` (429) выделены отдельно с русскими
текстами; 503 `not_configured`, 413 → `image_too_large`, 404 → `not_found`,
504 `model_timeout` → `timeout`, прочие 4xx → `bad_request`, 5xx → `server`;
сеть/таймаут/отмена → `network`/`timeout`/`aborted`, нечитаемый ответ →
`invalid_response`. Тесты распознавания (24) остались зелёными без правок.

## 3. Оцифровка (T10.2–3)

- `digitizeItem(id)` — **только явное действие**: строит промпт
  (`buildGenerationPrompt`), зовёт `POST /generate`, сохраняет результат с ролью
  `ai`. Повтор не создаёт вторую AI-версию: если роль `ai` уже есть, возвращается
  существующая (`status: 'уже есть'`).
- `digitizePackshot(id)` — вырез через `cutoutBlob`, роль `вырез`, **без
  генерации**. «Подозрительный» вырез (вещь светлая / фон не распознан) — понятная
  ошибка `cutout_failed`, а не сохранение невырезанного PNG под видом выреза.
- `digitizeAuto(id)` — выбор способа: пакшот → вырез, прочее → генерация. Если
  вырез пакшота всё же оказался подозрительным, честный откат на генерацию: вещь
  важнее сэкономленного запроса.
- `digitizeMissing()` — stateless-проход по вещам без выреза и без AI-версии;
  сбой одной не прерывает остальные. Массовая кнопка в UI идёт через **очередь**
  (T12), которая делает то же самое, но переживает закрытие приложения; обе
  опираются на `digitizeAuto`.
- **Оригинал только читается.** Производные изображения добавляются через
  `storage/images` (`add`), оригинал не перезаписывается и не удаляется;
  `idИзображений` вещи дополняется новым id. Тест сравнивает запись оригинала
  до и после (`toEqual`) и число оригиналов.
- Пометка «AI-версия» — только в карточке вещи (T15): здесь достаточно роли `ai`.
  Тест T13 «в сетке нет слова «AI»» по-прежнему зелёный.

## 4. Очередь (T12)

Состояние — одна запись `id: 'active'` в сторе `queue`, переписывается `put`-ом
после каждого шага. Задачи: `idВещи`, название, способ, статус
(`ожидает`/`в работе`/`готово`/`не удалось`), накопительные `попытки`, последняя
ошибка. Прогресс считается из состояния: `всего`, `обработано`, `успехов`,
`ошибок`, `осталось`, `текущая`, `последняяОшибка`.

- **Ретраи.** До 3 попыток на вещь с паузой (`DEFAULT_RETRY_DELAY_MS = 1000`,
  в тестах пауза нулевая). Исчерпали — задача «не удалось», очередь идёт дальше.
- **Сбой одной вещи не рушит остальные**: ошибка пишется в задачу, цикл
  продолжается; уже оцифрованное остаётся.
- **Фатальные ошибки** (`unauthorized`, `not_configured`, `no_original`,
  `not_found`) не ретраятся: очередь останавливается, текущая вещь возвращается
  в `ожидает`, а не помечается «не удалось» — токен можно починить и продолжить,
  ничего не теряется. Это осознанное отличие от «до 3 попыток»: повторять 401
  бессмысленно и вредно.
- **Возобновление.** Очередь персистится; при открытии приложения панель читает
  её (`refresh`) и показывает кнопку **«Продолжить оцифровку»**. Автозапуска нет:
  генерация без нажатия запрещена решением тикета. Если приложение закрыли на
  середине, сохранённый статус `выполняется` при `refresh` превращается в
  `остановлена`, а задачи из `в работе` — в `ожидает`.
- **Остановка по кнопке**: `stop()` отменяет текущий запрос (`AbortSignal`),
  возвращает вещь в очередь и сохраняет прогресс.

## 5. Миграция схемы v1 → v2

`DB_VERSION = 2`; в `upgrade()` добавлена ветка `case 1` → `createSchemaV2`
(создаёт стор `queue`), прошлые шаги не переписаны. Тест
`миграция v1→v2 на реальном upgrade()` открывает базу версии 1 через
`openDB(DB_NAME, 1, { upgrade })`, кладёт вещь и изображение, закрывает, затем
зовёт `getDb()` (он открывает уже версию 2 и вызывает рабочий `upgrade`):
вещи и изображения на месте, стор `queue` появился. Прежний тест проверял
тестовую ветку и при `DB_VERSION = 2` перестал бы запускать `upgrade` — он
заменён, а не оставлен рядом.

## 6. UI

`WardrobeScreen` получил одну строку: `{состояние === 'готово' && секции.length > 0 && <DigitizePanel />}`
после заголовка. Логика секций и сетки не тронута. Панель:
«Оцифровать всё, где нет пакшота» → во время работы полоса прогресса,
«Обработано X из Y · успешно A · ошибок B», «Сейчас: <название>», «Остановить»,
последняя ошибка; для прерванной очереди — «Продолжить оцифровку»; когда
оцифровывать нечего — «Всё уже оцифровано». Стили — на токенах ADR-0005.
Корень панели — `<section>` без `aria-label`, чтобы не добавлять десятый
landmark-регион и не ломать подсчёт секций T13.

Живой прогон (`raw/t10-t12-live.txt`): `GET /health` → `{"ok":true,"ai":true}`;
`POST /generate` без заголовка → 401 `unauthorized`; с заголовком →

(та же картина в `docs/evidence/raw/t11-live.txt`, коммит T11 отмечает квоту
нейронов). Клиент корректно разбирает тело ошибки и отдаёт код `server`; очередь
ретраит до 3 раз и продолжает остальные вещи — это доказано на моке воркера.

## 9. Не сделано / риски

- **Живой end-to-end генерации нет**: воркер сейчас отвечает 502 `model_error`
  (Workers AI / квота). Клиент, очередь и сохранение проверены на моке воркера;
  реальную картинку с устройства получить не удалось. Воркер не трогали.
- `digitizeMissing` и очередь дублируют цикл: первая — stateless-примитив для
  вызовов без персистентности и для тестов, вторая — UI-путь. Обе на `digitizeAuto`.
- fake-indexeddb не сохраняет `Blob` (после круга остаётся `{}`), а jsdom `Blob`
  не имеет `.text()`/`.arrayBuffer()`. Поэтому тесты проверяют неприкосновенность
  Оригинала структурно (сравнение записи), а не по байтам; в реальном браузере
  Blob хранится как Blob.
- `analyze` получил второй параметр (вещь): тестам нужно различать вещи, не читая
  Blob. Для `analyzeImage` он необязателен.
- Врезка в `WardrobeScreen` не меняет переход по карточке (по-прежнему `/`):
  это участок T15, трогать не стал.
- ~~`vite build` предупреждает, что `digitize.ts` и динамически импортируется из
  `digitizeBridge` (T15), и статически из очереди — это безвредно, чанк просто не
  выделяется.~~ **Исправлено fix-review:** прослойка `digitizeBridge.ts` удалена,
  предупреждение сборки ушло (см. `docs/evidence/T15.md`).

## 10. Спорные решения

| Решение | Почему так |
|---|---|
| Возобновление — кнопкой, а не автозапуском | «Фоновой генерации без нажатия не существует» (решение тикета). Показываем «Продолжить оцифровку», но не стартуем сами. |
| 401/`not_configured` останавливают очередь, вещь остаётся в `ожидает` | Повтор 401 не поможет, а пометить вещь «не удалось» — соврать: виноват токен, а не вещь. После починки токена очередь продолжается с того же места. |
| Способ оцифровки определяется по Оригиналу в момент обработки (`analyzeImage`) | В домене нет сохранённого флага «пакшот», а анализ рамки уже есть (T6). Решение принимается ровно тогда, когда нужен вырез. |
| Подозрительный вырез откатывается на генерацию | Вещь не должна остаться неоцифрованной из-за одной неудачной эвристики; лишний запрос дешевле потерянной вещи. |
| `queue` — отдельный стор, а не поле вещи | Очередь — служебная сущность, а не домен (`CONTEXT.md`); её состояние не должно попадать в `domain/types.ts`. Одна запись `active` достаточна для личного приложения. |
| `ClassifyError` — алиас `TidyApiError` | Два класса с одинаковыми кодами разошлись бы; `instanceof` и тексты теперь одни, тесты распознавания не менялись. |
| Тест миграции заменён, а не добавлен | Прежний тест проверял тестовую ветку `upgrade` и при `DB_VERSION = 2` не вызывал бы `upgrade` вовсе; оставлять его рядом — ложная уверенность. |
| Счётчик кнопок в тесте T13 сужен до секций | Панель добавляет свою кнопку на непустом гардеробе; глобальный `getAllByRole('button')` перестал быть мерой сетки. |
