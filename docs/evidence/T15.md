## 2. Изображение: переключатель и пометка AI

Правило «Решения» (уточнено решением D9): в сетке и коллаже изображение берётся в порядке
`ai` → `вырез` → `оригинал`; в карточке — переключатель, и только здесь живёт пометка об AI.
Реализация:

- по умолчанию открывается **AI-версия**, если она есть, иначе Оригинал; вырез не выбирается
  сам — он доступен переключателем (правило D9 не прячет его, но и не навязывает вместо Оригинала);
- переключатель из кнопок собирается из того, что реально есть: `Оригинал` всегда,
  `AI-версия` — только при наличии роли `ai`, `Вырез` — только при наличии роли `вырез`;
- одна опция → переключателя нет, показывается один оригинал без кнопок;
- пока показывается AI-версия, под изображением висит бейдж `AI-версия` (`role="note"`);
  для Оригинала и Выреза пометки нет — в сетке её тоже нет;
- из нескольких AI-версий берётся самая новая (перегенерация показывает свежий результат),
  из оригиналов — самый ранний; вырез не показывается по умолчанию.
## 3. Правка категории

`CategoryPicker` (таксономия ADR-0004) сохраняет правку сразу: `items.update(id, …)`
проставляет `датаОбновления` и возвращает обновлённую вещь в состояние экрана.
Отдельной кнопки «Сохранить» нет — правки не теряются при выходе. Тест читает вещь
из IndexedDB, закрывает и заново открывает БД (`closeDb`) и проверяет, что правка
пережила «перезапуск».

## 4. Удаление

Двухшаговое подтверждение встроено в экран (без `window.confirm`), потому что
`window.confirm` не тестируется в jsdom и плохо выглядит на телефоне. Репозиторий
`items.remove` каскадно удаляет оригинал и AI-версию; если вещь входит в образ,
возвращается `ОшибкаВещьВОбразе` — показывается понятный русский текст
(`Нельзя удалить: вещь входит в образ «…»`), вещь остаётся на месте.

## 5. Генерация AI-версии — только по нажатию

Кнопка `Сделать AI-версию` / `Перегенерировать` вызывает `digitizeItem(id)`.
Во время генерации кнопка блокируется и подписана «Готовим AI-версию…»; после
успеха изображения перечитываются из хранилища и выбирается AI-версия. Ошибки:

- код `unauthorized` → «Сервис оцифровки отклонил запрос (401). Проверьте доступ…»;
- код `rate_limited` → «Слишком много запросов на оцифровку (429). Подождите…»;
- прочее — сообщение сервиса, иначе общий текст.

Никакой фоновой генерации нет: тест проверяет, что до нажатия `digitizeItem` не
вызывается вовсе.

## 7. Тесты (`ItemScreen.test.tsx` — 10)

1. по id показывает название, цвета, состав, бренд, источник, дату и категорию;
2. без AI-версии переключателя нет, показывается оригинал;
3. при наличии AI-версии переключатель меняет изображение, бейдж «AI-версия» виден;
4. при наличии только выреза переключатель даёт Оригинал / Вырез без AI;
5. смена категории сохраняется в IndexedDB и переживает перезапуск БД;
6. вещь из образа не удаляется, показывается понятная ошибка, вещь на месте;
7. свободная вещь удаляется, оригинал и AI-версия уходят каскадом;
8. несуществующий id → «Вещь не найдена» и возврат в гардероб;
9. AI-версия создаётся только по кнопке и появляется после оцифровки;
10. ошибки 401 и 429 показываются человеческим текстом.

Воркер/сервис оцифровки в тестах карточки мокается (`vi.mock('../../services/digitize')`), хранилище —
`fake-indexeddb`, изображения — через подмену `URL.createObjectURL` с метками blob.

## 10. Спорные решения

| Решение | Почему так |
|---|---|
| По умолчанию в карточке показывается AI-версия, если она есть | Согласуется с правилом «в сетке и коллаже — AI-версия, если есть» и делает пометку «AI-версия» видимой сразу; пользователь одним нажатием возвращается к оригиналу. |
| Переключатель показывается и при одном вырезе без AI | Требование «если есть вырез, дай выбрать и его» иначе не выполнить: без переключателя вырез было бы не увидеть. Кнопка «AI-версия» при этом не рисуется. |
| Подтверждение удаления — встроенный блок, а не `window.confirm` | `window.confirm` не поддаётся проверке в jsdom и выбивается из ADR-0005; встроенный `role="alertdialog"` тестируем и одинаково выглядит на всех платформах. |
| Текст ошибки удаления собирается из `ОшибкаВещьВОбразе` | Репозиторий отдаёт русское сообщение с `id` вещи; имя образа достаётся из него, чтобы пользователю не показывать технический `id`. |

## 11. Исправления после независимого теста

Проверено 2026-10-14. Дефект 2 (важный): кнопка «Перегенерировать» ничего не
генерировала, потому что `digitizeItem` при наличии AI-версии делала ранний выход
`status: 'уже есть'` до вызова воркера.

### Что изменено

| Файл | Изменение |
|---|---|
| `src/services/digitize.ts` | в `DigitizeDeps` добавлен `force?: boolean`; `digitizeItem` при `force: true` игнорирует ранний выход, генерирует заново и **заменяет** прежнюю AI-версию: её id убирается из `вещь.idИзображений`, а само изображение удаляется через `images.removeNonOriginal`. Оригинал не трогается. Без `force` поведение прежнее (идемпотентный повтор). |
| `src/app/screens/ItemScreen.tsx` | «Сделать AI-версию» (AI ещё нет) вызывает обычный режим, «Перегенерировать» (AI есть) — `{ force: true }`. Позже (fix-review) прослойка `digitizeBridge.ts` удалена, импорт сервиса — прямой. |
| `src/services/digitize.test.ts` | +3 теста: force реально зовёт воркер и заменяет старую AI; force создаёт AI, если её не было; массовый проход пропускает уже оцифрованное даже при `force` в deps. |
| `src/app/screens/ItemScreen.test.tsx` | +1 тест: кнопка «Перегенерировать» вызывает `digitizeItem(id, { force: true })`, карточка показывает свежую AI-версию. |

### Почему так

- **Замена, а не накопление.** `images.add` не перезаписывает по id, поэтому новая
  AI-версия получает новый id. Чтобы не оставлять две AI-версии, старая удаляется
  через `removeNonOriginal` (метод запрещает удалять оригинал), а её id вычищается
  из `idИзображений`. Новое изображение сохраняется раньше удаления старого: если
  удаление сорвётся, пользователь всё равно получит свежую AI-версию.
- **Идемпотентность массовой оцифровки сохранена.** `digitizeAuto`,
  `digitizeMissing` и очередь (T12) не передают `force`; более того,
  `digitizeAuto` возвращает `уже есть` ещё до вызова `digitizeItem`, а
  `itemsNeedingDigitization` вообще не берёт вещи с готовой AI-версией. Фоновой
  генерации нет.
- **Байты Оригинала.** `fake-indexeddb` клонирует `Blob` в пустой объект без
  `size`/методов, поэтому сравнить байты в тесте нельзя. Неизменность Оригинала
  подтверждается идентификатором, ролью и единственностью записи: перегенерация
  не вызывает `addOriginal` и не передаёт оригинальный id в `removeNonOriginal`.
