## Как определяется фон

1. **Связность от рамки, а не порог белизны.** Близость к белому считается по
   min-каналу `min(r,g,b)`. Фоном объявляются пиксели с `min ≥ whiteThreshold`,
   **связанные с рамкой** (обход в ширину от краёв). Поэтому белый рисунок внутри
   вещи, не связанный с рамкой, остаётся непрозрачным.
2. **Мягкая кромка.** В переходной зоне `[whiteThreshold − transitionWidth, whiteThreshold]`
   альфа едет от 1 к 0 плавно, плюс зона заходит на `edgeRadius` пикселей внутрь вещи.
   Ступеньки нет: кромка получает несколько промежуточных уровней альфы.
3. **Однородность локального фона.** Для фоновых пикселей альфа умножается на
   локальную однородность (окно 3×3, только соседи-фон): однородный фон вырезается
   смелее, шумный/градиентный — консервативнее. Соседи-не-фон не учитываются, иначе
   вокруг вещи был бы серый ореол.
4. **Цвет не трогается.** Изменяется только канал альфы; RGB копируется байт-в-байт.
   Никакого умножения RGB на альфу — вещь не темнеет по кромке и не меняет оттенок.

Защита: если после выреза выживших (альфа ≥ 128) меньше `minSurvivorRatio` (2%),
результат отменяется — возвращается исходное изображение и `suspicious: true`.
Так светлая вещь на белом не превращается в пустой PNG.

### Параметры (`CutoutOptions`, значения по умолчанию)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `whiteThreshold` | `240` | порог белизны по min-каналу (как в детекторе пакшота T6) |
| `transitionWidth` | `40` | ширина мягкой переходной зоны в уровнях яркости |
| `edgeRadius` | `2` | на сколько px мягкая кромка заходит внутрь вещи |
| `aggressiveness` | `1` | 1 — фон вырезается полностью, меньше — остаётся полупрозрачным |
| `uniformityTolerance` | `8` | допуск однородности локального фона (окно 3×3) |
| `minSurvivorRatio` | `0.02` | ниже этой доли выживших результат отменяется (`suspicious`) |

## Тесты

`src/services/cutout.test.ts` — 10 тестов на синтетических пикселях:

- белый фон + однотонная вещь → рамка прозрачна, вещь нет, RGB до/после совпадает;
- почти-белый фон `250,250,250` → тоже вырезается;
- светлая вещь `240,240,235` на белом → сохраняется, выживших заметно больше 2%;
- серый фон → вырез ничего не меняет (`transparentRatio = 0`);
- белая деталь внутри вещи → остаётся непрозрачной (связность, не порог);
- кромка → есть два и более промежуточных уровня альфы, плотность растёт к вещи;
- целиком белое изображение → `suspicious: true`, пиксели не изменены;
- пустое/однопиксельное изображение → не падает;
- `aggressiveness: 0.5` → фон остаётся полупрозрачным (альфа 128);
- `cutoutBlob` в jsdom без canvas → понятная ошибка, а не тихий сбой.

## Ограничения и риски

- **Светлая вещь теряет ~1–2 px по контуру**: мягкая кромка заходит внутрь на
  `edgeRadius` и для светлой вещи даёт по краю частичную прозрачность. Внутренность
  и цвет сохраняются полностью. При необходимости `edgeRadius` уменьшается до 1.
- **Серый/цветной фон не вырезается** (нет почти-белой связной области) — это
  осознанно: такие фото идут в генеративную AI-версию (ADR-0002), а не в вырез.
- **Однородность локальная, а не глобальная**: мелкий шум по всему фону снизит
  прозрачность фоновых пикселей; для реальных WB-пакшотов фон гладкий.
- `cutoutBlob` в браузере не прогонялся автотестом (в jsdom нет canvas);
  проверена только понятность ошибки. Ручной/браузерный прогон — вне этой задачи.
