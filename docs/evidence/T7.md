Проверено 2026-10-14. Задача T7, ADR-0004. Коммиты и деплой — за координатором.

## 2. Источники и воспроизводимость

Все строки взяты из реальных данных WB, ничего не выдумано.

| Файл / URL | Размер | Как получен |
|---|---|---|
| `https://static-basket-01.wbbasket.ru/vol0/data/main-menu-ru-ru-v2.json` | 462 377 Б | `curl` → `docs/evidence/raw/wb-menu.json` |
| `https://static-basket-01.wbbasket.ru/vol0/data/subject-base.json` | 802 429 Б | `curl`, из него сделан срез релевантных корней → `wb-subject-base.fashion.json` (41 КБ) |
| `basket-*.wbbasket.ru/.../info/ru/card.json` | — | 5 реальных карточек (см. §3), `curl` |

**Почему `subject-base.json`, а не только витрина.** `main-menu-ru-ru-v2.json` — это дерево
*витрины* («Платья и сарафаны», «Кеды и кроссовки»), а `card.json` отдаёт `subj_name` из
*справочника предметов* («Платья», «Кеды»). Именно `subject-base.json` содержит те же пары
«корень → предмет» и те же числовые id, что и `data.subject_root_id`/`subject_id` карточки:
`Броши = subject_id 295` под `Бижутерия = subject_root_id 200`; `Платья = 69` под `Одежда = 1`;
`Костюмы спортивные = 4853` под `Спортивная одежда = 1513`.

Команды воспроизведения:

```bash
curl -sS -o docs/evidence/raw/wb-menu.json \
  https://static-basket-01.wbbasket.ru/vol0/data/main-menu-ru-ru-v2.json
curl -sS -o /tmp/subject-base.json \
  https://static-basket-01.wbbasket.ru/vol0/data/subject-base.json
# срез релевантных корней (Одежда, Обувь, Аксессуары, Белье, Головные уборы, Бижутерия,
# Ювелирные украшения, Ювелирная бижутерия, Аксессуары для волос, Спортивная одежда,
# Спортивная обувь, Аксессуары для обуви) → docs/evidence/raw/wb-subject-base.fashion.json
```

## 3. Сверка «справочник ↔ реальная карточка»

`docs/evidence/raw/wb-cards-sample.json` (полные заголовки — в `raw/t4-t5-t6-live.txt`):

| nm_id | `subj_root_name` | `subj_name` | `subject_root_id` | `subject_id` | id в `subject-base.json` |
|---|---|---|---|---|---|
| 16020837 | Бижутерия | Броши | 200 | 295 | 200/295 ✅ |
| 14058746 | Одежда | Платья | 1 | 69 | 1/69 ✅ |
| 14058741 | Одежда | Платья | 1 | 69 | 1/69 ✅ |
| 14058742 | Спортивная одежда | Костюмы спортивные | 1513 | 4853 | 1513/4853 ✅ |
| 14058739 | Красота | Эфирные масла | 49 | 2259 | 49/2259 ✅ (вне нашей таксономии) |

То есть названия из справочника совпадают с `subj_name`/`subj_root_name` карточки, а не
«примерно похожи». Строки корней, которых нет в нашей таксономии (Красота и т.п.), словарь
честно уводит в «Разное».

## 6. Спорные решения (и почему так)

| Строки WB | Решение | Почему |
|---|---|---|
| `Костюмы`, `Костюмы спортивные`, `Комбинезоны*`, `Полукомбинезоны` | «Разное» + `needsReview` | Верх и низ в одной вещи: ADR-0004 прямо называет этот случай. Одна наша категория соврёт, поэтому ручной выбор. |
| `Пижамы`, `* пижамные`, `Халаты*`, `Ночные сорочки`, `Пеньюары`, `Твинсеты`, `Карнавальные костюмы`, `Кигуруми` | «Разное» + `needsReview` | Комплект/домашняя одежда, которой нет в нашей двухуровневой таксономии. Не теряем, а просим выбрать. |
| `* купальники`, `Монокини`, `Танкини`, `Буркини`, `Костюмы купальные`, `Плавки` | Купальники → «Разное»; `Плавки` → Бельё/трусы | Купальник — отдельный класс, у нас его нет. Плавки по функции ближе к трусам. |
| `Болеро` | Второй слой/кардиган | Короткий трикотажный жакет: наш «Второй слой» ближе, чем «Верхняя одежда». Спорно, но не «Разное»: вещь узнаваема. |
| `Тапочки` | Обувь/сандалии | Домашняя обувь. Из подкатегорий (кроссовки/ботинки/сапоги/туфли/сандалии) ближе всего открытые сандалии; фиксируем как допущение. |
| `Часы наручные` | Аксессуары/украшения | Нет подкатегории «часы»; часы — личный аксессуар-украшение. |
| `Аксессуары для волос` (резинки, заколки, ободки…) | Аксессуары/украшения | Отдельной подкатегории нет; это украшение. |
| `Кошельки`, `Косметички`, `Портфели`, `Рюкзаки`, `Ранцы` | Аксессуары/сумка | Все — «несущие» аксессуары; подкатегория одна. |
| `Туники`, `Майки спортивные`, `Топы-бра` | Верх/топ | Туника — длинный топ, майка/бра — топ. |
| `Леггинсы`, `Тайтсы`, `Капри`, `Бриджи`, `Кюлоты` | Низ/брюки | Нет «леггинсов»; по крою это низ для ног, ближайшее — брюки. |
| `Кеды` | Обувь/кроссовки | Пример из тикета. |

`needsReview: true` ставится там, где мы не уверены (все строки, ушедшие в «Разное»), — UI
показывает их как «выберите категорию». Для «уверенных, но спорных» (Болеро, Тапочки, Часы)
флаг остаётся `false`, чтобы не заставлять жену подтверждать всё подряд; расхождение зафиксировано
в этой таблице и в комментариях к `WB_DICTIONARY`.

## 7. Поведение при неизвестном

`mapWbCategory(root, subject)` никогда не бросает и не теряет вещь:

- точная пара «корень + предмет» → `matchedBy: 'root+subject'`;
- корень не совпал (или пуст) → однозначный поиск по предмету → `matchedBy: 'subject'`;
- не найдено или неоднозначно → `{ top: 'Разное', sub: 'Разное', needsReview: true, matchedBy: 'none' }`.

Нормализация: регистр, `ё→е` (корень WB «Белье» ↔ наша «Бельё»), кавычки, скобки/точки,
пробелы, пометка `18+`; множественное/единственное число — автоматически (`-ки→-ка`,
отсечение `-ы/-и`), плюс `WB_SUBJECT_ALIASES` для разговорных синонимов (`кроссы→кроссовки`,
`майка→топы`, `балахон→худи`).

Коллизии исключены: если один `subj_name` в разных корнях вёл бы в разные наши категории,
индекс по предмету помечает его как неоднозначный (тест `нет коллизий` проверяет это
программно и требует одного исхода на строку).

## 8. Вход «фото» — `src/services/classify-photo.ts`

- **Эндпоинт:** `POST {baseUrl}/classify`, тело `{imageBase64, mimeType}`, ответ
  `{category, subcategory, confidence}`, ошибки `{error:{code,message}}` (сверено с воркером
  `workers/api/src/index.ts`).
- **Базовый URL:** `import.meta.env.VITE_TIDY_API_URL`, default
  `https://tidy-api.megabaff2011.workers.dev`; тип добавлен в `src/vite-env.d.ts`.
- **Размер:** лимит воркера 4 МБ на JSON-тело. Проверяем **до** отправки оценкой
  `base64len + обвязка`. Если фото больше — ужимаем в canvas до 2000 px по длинной стороне и
  перекодируем в JPEG (как делает vision-провайдер), и только потом шлём. Если canvas недоступен
  или после сжатия всё ещё больше — понятная ошибка `image_too_large`, без «молчаливого» 413.
- **Память:** Blob читается через `arrayBuffer()` (с fallback на `FileReader` для jsdom/старых
  webview), base64 собирается кусками по 32 КиБ — без спреда всего массива в `String.fromCharCode`.
- **Валидация ответа:** принимается только пара, прошедшая `isKnownTop` + `isKnownSub`; если
  верх соврал, но подкатегория однозначно чья-то — владелец восстанавливается; всё прочее →
  «Разное»/«Разное» + `needsReview: true`.
- **Ошибки (коды `ClassifyError`):** `not_configured` (503), `image_too_large`, `unsupported_media`,
  `bad_request` (4xx), `server` (5xx), `invalid_response`, `network`, `timeout`, `aborted`.
  `confidence` зажимается в [0, 1].

## 10. Не сделано / риски

- Словарь — стартовая точка: редкости («Пантолеты», «Луноходы», «Шармы ювелирная бижутерия»)
  покрыты, но новые предметы WB появятся и потребуют добавления строк. Для этого есть
  `unknownSubjects()` и `needsReview`.
- Строки вне наших корней (Красота, Дом, Зоотовары и т.п.) по определению уходят в «Разное» —
  это ожидаемо, а не пробел.
- Живой прогон `POST /classify` не делался: нужен секрет `OPENCODE_API_KEY` в воркере (T3).
  Клиент проверен на моке `fetch` строго по опубликованному контракту.
- `Туники`/`Плавки`/`Болеро`/`Тапочки`/`Часы` — осознанные допущения; при живом использовании
  легко перегнуть одной строкой словаря.
