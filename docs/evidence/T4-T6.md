## Таблица лоадеров и перебор

`BASKET_RANGES` в `card.ts` — диапазоны `vol → basket-{NN}` (basket-01: 0–143, basket-02: 144–287, …).
Оба живых случая в неё укладываются. Поверх — `basketCandidates(nmId)`: расчётный лоадер и до трёх
соседних (`[predicted, predicted-1, predicted+1, predicted+2]`, без нуля, максимум 4 попытки).
`loadWbCard` идёт по кандидатам, пока `card.json` не ответит `200`. За пределами таблицы `vol`
лоадер экстраполируется тем же шагом (216), а перебор подстрахует.

## Пороги пакшота (T6)

- рамка — 6% от меньшей стороны;
- «почти белый» — все каналы ≥ 240; `whiteness` — доля таких пикселей на рамке;
- `uniformity` — доля пикселей в доминирующем квантованном цвете рамки (4 бита/канал, допуск 24);
- `isPackshot = whiteness ≥ 0.80 && uniformity ≥ 0.75`.

Почему такие пороги: у реального пакшота 14058746 рамка даёт `whiteness` 0.87–0.89 (низ вещи
заходит в кадр, поэтому не 1.0), а у фото на модели — 0.00. Порог 0.80 отделяет их с запасом.
Серая однородная рамка режется по `whiteness`, сильный градиент — по `uniformity` (~0.30).
Синтетика в тестах: белая рамка → пакшот; серая → нет; светлая с текстом на ~трети пикселей
рамки → нет; градиент → нет; почти белая рамка с ~15% пикселей вещи → пакшот.
Ограничение: мелкий водяной знак может не отсечься — эвристика смотрит только на рамку.

## Замечания и решения

- **Состав.** Из `options[]`, где в имени есть «Состав»; если таких нет — фолбэк на `compositions[]`
  (у реального 14058746 состав лежит именно там, в опциях «Состава» нет). Не противоречит T5,
  но покрывает живые данные.
- **`buildCardUrl(nmId, basketNumber?)`.** Лоадер — второй параметр; по умолчанию берётся расчётный,
  поэтому `buildCardUrl(nmId)` тоже работает. Иначе URL не собрать без номера лоадера.
- **Ошибки — исключения** (`ОшибкаСсылкиWildberries`/`ОшибкаЗагрузкиКарточки`), как принято в
  `src/storage/errors.ts`; тексты русские и показываются пользователю.
- **Таймаут** — один `AbortController` на всю загрузку (~10 с), сигнал прокидывается в каждый `fetch`.

## Исправления после независимого теста (дефект 3)

Проверено 2026-10-14. Дефект 3 (минорный): `fetchJson` в `src/services/wb/card.ts`
глушил любую ошибку и возвращал `null`, поэтому при недоступной сети пользователь
видел «Товар не найден на складах Wildberries» для валидной ссылки.

### Что изменено

| Файл | Изменение |
|---|---|
| `src/services/wb/errors.ts` | `ОшибкаЗагрузкиКарточки` получила `code: 'not_found' \| 'network'` (по умолчанию `not_found`) и `cause`; базовая `ОшибкаWildberries` принимает `cause`. |
| `src/services/wb/card.ts` | `fetchJson` возвращает размеченный результат `ok` / `missing` (404) / `network` (fetch бросил, таймаут, 5xx и прочий не-404). `loadWbCard` на `network` прекращает перебор лоадеров и бросает `ОшибкаЗагрузкиКарточки` с `code: 'network'`; на `404` продолжает перебор; если 404 на всех — `code: 'not_found'`. `sellers.json` необязателен: его сбой карточку не отменяет. |
| `src/services/import-item.ts` | `какОшибкаИмпорта` маппит ошибку карточки по `code`, а не по подстроке в тексте: `network` → `ОшибкаИмпортаВещи('network')`, иначе `not_found`. |
| `src/services/wb/card.test.ts` | Обновлён прежний тест «переживает сетевые сбои» и +3 теста. |
| `src/services/import-item.test.ts` | +2 теста: сетевой сбой на входе «ссылка» даёт код `network`, 404 на всех лоадерах — `not_found`. |

### Поведение перебора лоадеров

- **404** — товара нет именно на этом лоадере: идём к следующему кандидату.
- **Сетевой сбой** (fetch бросил, таймаут по `AbortController`, 5xx/иной не-404
  статус) — искать по соседним складам бессмысленно: перебор прерывается, а
  пользователь получает текст про соединение, не «товар не найден».
- Таймаут (сигнал `aborted`) сообщается фразой «Wildberries не ответил вовремя…»,
  остальные сетевые сбои — «Не удалось связаться с Wildberries. Проверьте
  соединение и попробуйте снова». У обеих ошибок `code === 'network'`.

### Тесты

- `всегда бросающий fetch → code network` (и текст не содержит «не найден»);
- `5xx → code network`;
- `404 на всех лоадерах → code not_found`;
- `404 на первом лоадере и успех на втором → вещь загружается`;
- на уровне импорта: сетевой сбой → `ОшибкаИмпортаВещи('network')`,
  404 → `ОшибкаИмпортаВещи('not_found')`.

## T5-fix — честный перебор basket-лоадеров

Найдено живой проверкой на реальной ссылке. Проверено 2026-10-14.

### Симптом

`https://www.wildberries.ru/catalog/1318303621/detail.aspx` (товар существует) давал
«Не удалось связаться с Wildberries. Проверьте соединение и попробуйте снова».

### Причины

1. **Таблица экстраполирует неверно.** `vol=13183` лежит на `basket-45`, а `BASKET_RANGES`
   (до `basket-25, to 4565`) продолжала шаг 216 и давала `25 + ceil((13183−4565)/216) = 65`.
   Рост числа лоадеров не линеен: большие `vol` попадают в середину диапазона, а не в конец.
2. **Лоадеров 66+ не существует** (`basket-66.wbbasket.ru` → NXDOMAIN), но `basketCandidates`
   их предлагала. DNS-провал `fetch` трактовался как «сеть недоступна» и **прерывал** перебор.
3. **Таблица ненадёжна и для старых товаров**: `14058746` на расчётном `basket-01` отдаёт 404
   (спасал только перебор соседей).

### Что изменено

| Файл | Изменение |
|---|---|
| `src/services/wb/card.ts` | `MAX_BASKET = 65`; `basketForVol`/`basketCandidates` не выдают хостов вне `1..65`; новый `remainingBaskets` — полный список существующих лоадеров в порядке удалённости от расчётного; `fetchJson` с отдельным таймаутом 3 с; `isDnsFailure` отличает NXDOMAIN от сети; `loadWbCard` идёт «кэш → расчётный → соседи», затем параллельный перебор `01..65` (6 одновременно), общий дедлайн 10 с, остановка на первом 200. |
| `src/services/wb/basket-cache.ts` | новый модуль: найденный лоадер для `vol` в `localStorage` (`tidy.wb.basket.vol.<vol>`). При 404 по кэшу — обычный перебор, поэтому неверная запись не ломает загрузку. |
| `src/services/wb/card.test.ts` | +регресс-набор: границы `1..65`, NXDOMAIN не прерывает перебор, находка на далёком `basket-45`, все 404 → `not_found`, все таймауты/сеть → `network`, параллелизм ≤ 6, кэш (повтор, неверная запись, запись вне диапазона). |
| `src/__independent__/e2e.test.tsx` | бывший тест «перебор ограничен 4» заменён на «перебран весь диапазон `01..MAX_BASKET`» — это сознательное изменение поведения T5-fix. |
| `tools/t5-fix-live.ts` | новый скрипт живой проверки (запросы/мс/лоадеры, кэш). |

### Различение DNS и сети

- **NXDOMAIN / `ENOTFOUND` / `EAI_AGAIN` / `ERR_NAME_NOT_RESOLVED`** → «этого лоадера нет»:
  кандидат пропускается, перебор продолжается.
- **Настоящий сетевой сбой/таймаут** → ошибка `network`, и только если ни один кандидат вообще
  не ответил (ни 200, ни 404). Если хоть один лоадер ответил 404 — это `not_found`.
- **Сообщения:** все 404 → «Товар не найден на складах Wildberries»; реальная недоступность →
  «Не удалось связаться с Wildberries. Проверьте соединение и попробуйте снова» (таймаут —
  «Wildberries не ответил вовремя…»).

### Живая проверка (`docs/evidence/raw/t5-fix-live.txt`)

`npx vite-node tools/t5-fix-live.ts`:

| nmId | что это | лоадер | запросов | мс |
|---|---|---|---|---|
| 1318303621 | регресс: брюки джоггеры | **45** | 27 | 471 |
| 14058746 | контроль: платье | 01 | 2 | 98 |
| 14058741 | контроль: платье | 01 | 2 | 48 |
| 16020837 | контроль: брошь | 02 | 2 | 91 |

### Порядок кандидатов

Кэш (если есть) → расчётный по таблице → ближние соседи (`±1, +2`) → все остальные `01..65`
параллельно (6 за раз, по возрастанию расстояния от расчётного). Это быстро для частых товаров
и не зависит от истинности таблицы.
