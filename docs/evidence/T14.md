## 2. Чистая логика: `src/services/wardrobe-filter.ts`

Модуль без React, без сети и без IndexedDB — только доменные `Вещь`.

- `filterItems(items, filter)`: условия соединяются по «И». Внутри условия
  «цвета»/«сезоны» — по «ИЛИ» (достаточно любого выбранного значения). Пустой
  фильтр (`{}`, пустые строки, пустые массивы) возвращает всё.
- Верхняя категория сравнивается с учётом «Разное»: вещь с неизвестной
  категорией попадает в `FALLBACK_TOP`, как в `groupByTopCategory` T13, и
  находится по чипу «Разное».
- `searchItems(items, query)`: по названию, регистронезависимо, с `ё → е`, по
  подстроке. Пустой запрос возвращает всё.
- `filterAndSearch(items, filter, query)` — единая точка входа экрана:
  сначала фильтр, затем поиск.
- `availableColors(items)` — только цвета, реально встречающиеся в гардеробе,
  без пустых значений, по алфавиту. `availableSeasons(items)` — только
  встречающиеся сезоны в порядке `зима, лето, демисезон`. `availableSubcategories`
  — подкатегории выбранной верхней категории, известные в порядке ADR-0004,
  незнакомые — по алфавиту следом.
- **Бренда и цены нет** — прямо запрещено решением пользователя. Поэтому
  `searchItems` тоже ищет только по названию (не по бренду и не по составу).

## 3. Поведение экрана: полки или плоский результат

- Пока **фильтр и запрос пусты** — сохраняются секции-полки T13 (ничего не
  изменилось, тесты T13 проходят без правок).
- Как только задан **любой фильтр или запрос** — показывается **плоский**
  результат единой сеткой, счётчик «Найдено N» (`role="status"`) и кнопка
  «Сбросить фильтры». Полки после сужения теряют смысл, а счётчик отвечает
  на вопрос «сколько нашлось». Это поведение покрыто тестом
  `фильтр по верхней категории даёт плоский результат со счётчиком…`.
- Чипы верхних категорий и подкатегорий, цветов и сезонов строятся **только из
  того, что реально есть в гардеробе** — пустых чипов нет. Подкатегории
  появляются только после выбора верхней категории и зависят от неё.
- Активные чипы залиты терракотовым акцентом `#C05B3F` (ADR-0005), повторное
  нажатие снимает условие. «Сбросить фильтры» очищает и запрос, и фильтр.
- Когда ничего не нашлось — состояние «Ничего не найдено» с предложением
  изменить запрос или сбросить фильтры и кнопкой сброса. Чтобы не было двух
  одинаковых кнопок, в панели управления сброс показывается только при
  непустом результате, а в пустом состоянии — в самом блоке.
- Дизайн по ADR-0005: подложка карточек и состояний `#F6F6F4`, акцент `#C05B3F`
  на активных чипах, скругления чипов 12px, анимации 150–200 ms
  (`--motion-fast`/`--motion-base`), системный шрифт.

## 4. Данные для фильтра по сезону (осознанное расширение T14)

У вещи есть `сезон[]`, но при импорте по ссылке и по фото он пуст, а в карточке
вещи (T15) не было правки сезона и цветов — фильтру по сезону нечем было
наполниться. Поэтому в рамках T14 добавлено **редактирование сезона и цветов в
карточке** (это расширение зафиксировано здесь, как просил тикет):

- сезон — мультивыбор чипами `зима / лето / демисезон`;
- цвета — мультивыбор чипами: палитра частых цветов `ПАЛИТРА_ЦВЕТОВ` плюс цвета
  самой вещи (чтобы не потерять свободные строки из карточек WB);
- сохранение — сразу в IndexedDB через `items.update`, без кнопки «Сохранить»;
  при сбое оптимистичная правка откатывается и показывается понятная ошибка;
- строки «Цвета» в списке атрибутов больше нет — её заменили чипы; тест T15
  обновлён соответственно.

## 5. Скорость «нужная вещь за пару секунд»

Данные читаются из IndexedDB **один раз** при монтировании экрана (и по кнопке
«Повторить» при ошибке). Поиск и фильтры работают в памяти через `useMemo`:
ввод в поле не запускает повторное чтение. Это проверено тестом
`ввод в поиск не перечитывает IndexedDB: данные читаются один раз, фильтрация — в памяти`:
после ввода в поиск `loadWardrobe` вызван ровно один раз.

Замер (`fake-indexeddb`, jsdom), тест `50 вещей: filterAndSearch укладывается в порог`
создаёт 50 вещей и измеряет `filterAndSearch` по верхней категории, цвету и запросу:

```text
[T14 perf] filterAndSearch на 50 вещах: 0.03 мс
```

| Операция | Факт | Порог в тесте |
|---|---|---|
| `filterAndSearch` (50 вещей) | ~0.02–0.05 мс | `< 50 мс` |

Порог намеренно с большим запасом: это защита от регрессии (случайного
обращения к IndexedDB или N+1 на каждый ввод), а не микробенчмарк. Сложность —
один линейный проход по вещам.

## 8. Не сделано / риски

- В рабочем дереве параллельно видны чужие правки (HelpScreen/AppLayout/OutfitsScreen
  и т.п.) от других исполнителей; они не трогались и никак не связаны с T14.
- Цвета — свободные строки; `availableColors` сравнивает их точно. Два написания
  одного цвета (`чёрный` и `черный`) дадут два чипа. Нормализация цветов не
  вводилась: это доменное решение шире T14.
- Палитра для правки цветов — фиксированный список частых цветов плюс цвета
  вещи. Экзотический цвет, которого нет ни в палитре, ни у вещи, чипом не
  добавить; произвольный ввод цвета не делался.
- Замер снят на `fake-indexeddb` в jsdom, а не на реальном IndexedDB Safari:
  проверяется сложность и отсутствие обращений к хранилищу, а не абсолютное
  время на iPhone.

## 9. Спорные решения

| Решение | Почему так |
|---|---|
| При активном фильтре — плоский результат, без полок | После сужения полки дают пустые заголовки; плоский список со счётчиком «Найдено N» отвечает на вопрос «сколько и что нашлось». Поведение зафиксировано тестом. |
| Поиск только по названию, без бренда и состава | Тикет прямо запрещает бренд как критерий. Состав в поиск не добавлен, чтобы не превращать его в скрытый фильтр по неатрибутированным данным. |
| Верхние категории и подкатегории — одиночный выбор, цвета и сезоны — мультивыбор | Верх/под — взаимоисключающие уровни таксономии (как табы/чипы T17); цвет и сезон у вещи множественные, «ИЛИ» внутри условия естественно. |
| Списки чипов строятся по гардеробу, а не по таксономии | Требование «не показывать пустые чипы»; для цветов и сезонов это прямо указано, для категорий — то же по смыслу. |
| `availableSubcategories` добавлен в чистый модуль | Логика «что показать в чипах» проверяема без React; экран использует её и остаётся тонким. |
| Правка сезона/цветов в карточке — оптимистичная, с откатом при сбое | «Пара секунд» на телефоне: интерфейс откликается сразу, а при ошибке IndexedDB возвращает прежнее значение и показывает текст ошибки, чтобы правка не терялась молча. |
| Дублирующая кнопка сброса убрана из панели при пустом результате | Две одинаковые кнопки «Сбросить фильтры» на экране путают и ломают однозначность доступного имени; сброс остаётся ровно в одном месте в каждом состоянии. |
