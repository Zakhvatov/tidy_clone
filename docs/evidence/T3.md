# T3 — Worker-посредник

Проверено координатором 2025-10-14. Воркер задеплоен: `https://tidy-api.megabaff2011.workers.dev`,
версия `ba43c5bf-55fb-4644-a984-9d6b6c87d3b4`. Секрет `OPENCODE_API_KEY` установлен через
`wrangler secret put` (в репозитории секрета нет).

## «Готово когда»

| Требование | Доказательство |
|---|---|
| PWA получает картинку с любого устройства | `POST /generate` с edge: 200, `image/jpeg`, 1024×1024, реальные байты |
| Секреты только в воркере | `OPENCODE_API_KEY` — только через `env`, установлен как secret; тест «нет ключа → 503 `not_configured`»; тест на отсутствие утечки секретов и стектрейсов |
| Категория по фото | `POST /classify` → фиксированная таксономия ADR-0004, фолбэк «Разное»; 47 unit-тестов |

## Живые прогоны

```text
$ curl https://tidy-api.megabaff2011.workers.dev/health
{"ok":true,"ai":true}

$ curl -X POST .../generate -d '{"prompt":"a red hoodie, ..."}'
http=200 type=image/jpeg bytes=19139
/tmp/gen.jpg: JPEG image data, 1024x1024, components 3

$ curl -X POST .../classify -d '{"imageBase64":"AAAA...","mimeType":"image/jpeg"}'   # 12 КБ, мусорный base64
http=502 {"error":{"code":"model_error","message":"Сервис распознавания вернул ошибку (400)"}}

$ curl -X POST .../classify -d '{"imageBase64":"aaaa","mimeType":"image/jpeg"}'      # минимальное тело
http=502 {"error":{"code":"model_error",...}}      # доходит до воркера, ошибка провайдера — честная

$ curl -X POST .../classify -d '<8 КБ: первые 6 КБ реального JPEG>'
http=200 {"category":"Разное","subcategory":"Разное","confidence":0}   # обрезанное фото — честное «Разное»
```

Прямая проверка провайдера с полной картинкой (25 КБ): 200 за 6.2 с,
`{"category":"Одежда","subcategory":"Толстовка"}` — то есть с заголовком `x-opencode-session`
vision-путь рабочий.

## Найденный и исправленный дефект

`/classify` падал с 400 `MissingSessionID`: провайдер `opencode-go` требует заголовок
`x-opencode-session` (любой UUID на диалог). Исправлено, заголовок покрыт тестом.
Заодно `withTimeout` заменён на `fetchWithTimeout` с настоящим `AbortController`: без отмены
подвисший подзапрос оставлял воркер без ответа и рвал клиентское соединение.

## Ограничение проверки (важно)

Тело запроса больше ~16 КБ с этой машины не доходит до Cloudflare вообще: `wrangler tail` не видит
запроса, граница воспроизводится и на `text/plain`. Это локальная сеть разработчика (Cisco AnyConnect
Socket Filter), а не дефект воркера. Разбор — `docs/decisions-log.md`, D4. Полный сквозной вызов
`/classify` с большой картинкой нужно перепроверить с обычной сети (шаг человека / финальный E2E).

## Hardening (T3-hardening, 2026-10-14)

Живые проверки: `docs/evidence/raw/t3-hardening-live.txt`. Deploy Version ID
`d2b9817e-0998-4f04-8c47-90fcb599c7b4`.

### Что закрыто

| Замечание | Решение |
|---|---|
| Лимит тела обходится без `Content-Length` (chunked) | `readJsonObject` читает `request.body` reader'ом, считает байты и при превышении сразу делает `reader.cancel()` → 413. Если `Content-Length` уже больше лимита — 413 без чтения. Покрыто тестами: ровно на границе, +1 байт, chunked сверх лимита |
| Эндпоинты открыты для `curl` | Секрет `CLIENT_TOKEN` (поставлен через `wrangler secret put`); заголовок `x-tidy-client` на `/generate` и `/classify`, неверный/пустой → 401 `unauthorized`, нет секрета → 503 `not_configured`. Сравнение — constant-time XOR без раннего выхода |
| Нейроны жгут анонимно | `ratelimits` в `wrangler.jsonc`: `GENERATE_RATE_LIMITER` 20/60 c, `CLASSIFY_RATE_LIMITER` 40/60 c; ключ — SHA-256 от IP; при отказе 429 `rate_limited`; отсутствие/сбой лимитера не роняет сервис (fail-open) |
| `withTimeout` не отменяет `ai.run` | `env.AI.run(model, input, { signal })` с настоящим `AbortSignal` — по таймауту подзапрос отменяется |
| Коды ошибок — свободные строки | `ApiErrorCode` — union-тип в воркере; `ClassifyErrorCode` в корне |
| `topCategories()` без «Разное» | Приведено к корневому `src/domain/taxonomy.ts`: «Разное» в списке, `subcategoriesOf`, `isKnownCategory`, `isKnownSubcategory` |
| CORS превью Pages | Разрешён ровно один превью-поддомен: `https://<hash>.tidy-clone.pages.dev` (суффикс с точкой, вложенные поддомены и похожие домены — нет) |
| Клиент не шлёт токен, глухие 401/429 | `classify-photo.ts` шлёт `x-tidy-client` из `VITE_TIDY_CLIENT_TOKEN`, коды `unauthorized` и `rate_limited` переведены в понятные русские ошибки |

Живая проверка: `/health` 200; `/generate` без токена 401; с токеном 200 `image/jpeg`;
тело 16385 Б → 413; 25 быстрых запросов → 20 проходят, дальше 429; preflight с превью-поддомена → 204.

### Осталось открытым / риски

1. **Полное тело картинки не скачивается с этой машины.** `/generate` с токеном отдаёт 200
   `image/jpeg`, `content-length` ~247 КБ, но локальная сеть обрывает приём на ~19 КБ (D4).
   Заголовок JPEG валиден (1024×1024), но целостность всего файла подтверждена только на уровне
   статуса/типа. Финальный E2E с обычной сети — шаг человека.
2. **PWA на Pages пересобран координатором с токеном.** `VITE_TIDY_CLIENT_TOKEN` вшивается Vite
   на сборке; Pages задеплоен с ним (токен присутствует в `dist/assets/*.js`), поэтому фото-распознавание
   из веба не получит 401. Порядок выката: любой будущий `npm run deploy` обязан идти с заполненным
   `.env.local`, иначе распознавание фото вернёт 401.
3. **Токен ротирован.** Старое значение попало в `.env.example`/`.dev.vars.example` и в git-историю,
   поэтому координатор сгенерировал новый токен, поставил его секретом воркера и положил в
   незакоммичиваемый `.env.local`; в примерах теперь заглушки. Старое значение — мёртвое (живой
   запрос с ним даёт 401). Отдельно: этот токен по конструкции уходит в публичный бандл PWA
   (префикс `VITE_`), то есть его «секретность» номинальна — это заслон от случайных сканеров,
   а не аутентификация. Настоящая защита (Cloudflare Access/Turnstile) — за пределами объёма,
   внесена в остаточные риски.
4. `namespace_id` лимитеров (`1001`, `1002`) выбраны произвольно — при конфликте в аккаунте сменить.
